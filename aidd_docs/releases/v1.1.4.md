# PEA Tracker v1.1.4 — Restore MCP and independent financial approval

24 November 2026. Corrective release preserving V1.1 financial rules and historical
V1 read contracts. No V2 implementation is included.

## Changes

- MCP admission can explicitly accept the exact configured read/browser audience
  pair, while requiring the read audience, valid signature, issuer, lifetime and
  exact owner. Unknown, duplicate or extra audiences remain rejected. The reason
  the issuer combined the audiences remains unresolved.
- MCP identity never grants browser approval permission. The independent browser
  channel still requires its single dedicated audience and exact owner. A separate
  browser relay forwards protected confirmation requests through a service binding;
  it has no financial D1 binding or owner secrets.
- Native confirmation forms use `Referrer-Policy: strict-origin`. The previous
  `no-referrer` policy caused native POSTs to carry `Origin: null`, which the server
  correctly refused. Exact Origin, same-origin fetch metadata, CSRF, expiry and
  one-use proposal approval remain enforced; null Origin is not accepted.
- Guarded read-only recovery and browser identity diagnostics support isolation.
  Both are disabled in the normal deployed configuration; financial writes and
  explicit known-pair MCP admission are enabled.

  negative/failure scenarios and internal receipt-store inspection remain
  unvalidated by that nominal report; separate local evidence is retained.
