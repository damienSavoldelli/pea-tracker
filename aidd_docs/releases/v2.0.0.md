**Prepared for review; not released or deployed.** The eventual tag, accepted main

## Scope

V2.0 integrates the A–E workstreams while preserving the V1.1.5 financial discovery
and independent approval model. It prepares multi-portfolio consultation and
separate real/simulated financial circuits without changing financial formulas
or placing brokerage orders.

- Owner-scoped registry with immutable opening anchors and deterministic adoption
  of the existing portfolio. Administrative creation remains an internal capability,
  not a public MCP tool or REST endpoint.
- Versioned read-only REST `/api/v2/portfolios` and MCP discovery, details, state and
  valuation. Registry discovery replaces the V1 singleton only when present; there
  is exactly one `list_portfolios` registration. Historical V1.1 contracts remain.
- Real operations retain independent browser approval, exact intent/digest, expiry
  and idempotent receipts. Simulated operations use a separate explicit confirmation
  circuit and cannot authorize real writes. Owner/kind/anchor/archive guards apply.
- Multi-provider mapping, normalization, provenance and source-time nonregression
  are available in isolated observation components. Yahoo remains primary.
- Configurable collector cadence supports 15 minutes while keeping the existing
  30-minute default. Session-reuse experiments remain outside the active collector.

## Operational boundaries

- Yahoo primary; EODHD observation only, no active fallback.
- Marketstack/Alpha Vantage remain conditional historical-close candidates.
- EODHD equivalence to unadjusted last trade is not demonstrated.
- Production cadence stays 30 minutes; shared-session optimization stays inactive.
- Individual venue modes/intraday phases and some hosted negative/failure scenarios
  remain unqualified. Existing freshness warnings and unavailable states remain.
- No real or simulated transaction on the real PEA was used for this preparation.

## Delivery requirements

The [delivery procedure](v2.0.0-delivery.md) requires verified backup/isolated restore,
actual adoption checks, preserved configuration and Access protection, then migrations
0008 → 0009 before the V2 financial Worker. Do not replay 0007 against a populated
journal. A Worker rollback does not restore D1 or OAuth configuration.

[Actual snapshot backup/local restoration/adoption](v2.0.0-recovery-validation.md)
subsequently passed. Whole-Worker Access coverage is owner-reported. Hosted
read-only acceptance, independently recoverable backup/key arrangements,
ongoing retention/capacity oversight and explicit owner delivery approval remain
pending. Initial capacity fits the acquired 30-minute/12-month sizing envelope;
this does not establish indefinite retention or automatic backup rotation.
**Production execution is NO-GO until those gates are satisfied.** Publish the tag/release only after the accepted deployment and record
the exact final revision. Do not attach private captures, configuration or exports.
