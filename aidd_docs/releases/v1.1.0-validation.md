## Post-publication RETEX — authentication incident, 24 November 2026

This later incident does not rewrite the V1.1.0 publication evidence above.
See the [incident record, tests and recovery limits](../tasks/2026_11/2026_11_21_financial-mcp/authentication-incident-2026-11-24.md).

- **Symptom:** owner MCP ping and reads returned HTTP 401 before tool execution.
  Allowed Access login events did not establish successful Worker authentication.
- **Verified immediate cause:** signed assertions contained the configured MCP and
  browser audiences together; the application's singleton-AUD guard rejected them.
  Why the issuer supplied both audiences remains unresolved.
- **Unsuccessful mitigations:** Worker rollback, approval cookie path enforcement,
  separate approval hostname and parking its Access destination did not establish
  recovery in the reported attempts. Repeated reconnection was not diagnostic proof.
- **Temporary recovery:** an explicitly authorized, opt-in MCP read-only mode permits
  only that exact known audience pair, with signature/issuer/time/owner checks intact.
  It cannot coexist with financial writes; browser approval remains disabled.
- **Evidence:** 13 new targeted recovery tests, four existing targeted financial
  tests, typecheck and dry-run passed. Recovery Worker
  `805050ee-3965-49de-b1a2-b7f57c584d8f` was deployed; the owner supplied a successful
  ChatGPT ping at `2026-11-24T05:55:35.873Z`. This proves that call, not financial
  read correctness or the complete browser/write/receipt/replay journey. No real
  financial operation was created or confirmed by these checks.
- **Process lesson:** capture a correlated request, deployed version and precise
  server rejection before changing configuration. Bound each experiment to a
  hypothesis and stop ineffective retries. State local/deployed/operational status
  explicitly; do not call a reversible mitigation a root-cause fix.
- **Additional operational evidence:** at 06:56:54 Europe/Paris on 24 November,
  the owner reported a successful direct `get_current_portfolio_valuation`, using
  Yahoo unadjusted last-trade data, covering all 20 expected positions and returning
  cash/performance without HTTP 401. This validates that financial read call beyond
  ping, not every tool or independent calculation reconciliation. Private IDs,
  amounts and quantities are omitted. Subsequent presentation/simulation is not a
  recorded operation; writes and approval remain disabled.
- **Follow-up:** qualify the assertion's issuance and independent approval before
  restoring writes. Calendar duration, active time and avoidable investigation cost
  have not been reconstructed; do not invent them.

## Still unvalidated or explicitly limited at publication

- First real owner-authenticated browser approval, exact write, unique receipt,
  replay and resulting projected reads in production. No synthetic transaction
  may be recorded in the real PEA to close this gate.
- Production refusal/recovery for every expired/altered intent, concurrent approval
  or interrupted append is not claimed from anonymous boundary checks. Local coverage
  exists. If approval was consumed but no receipt exists, fail closed and reconcile;
  do not automatically rearm or blindly duplicate the operation.
- Scheduled ChatGPT financial approval is not an accepted path: MCP has no browser
  approval permission, and a client confirmation flag is insufficient. A scheduled
  `ping` reported by the owner does not validate unattended financial writes.
- Individual continuous/fixing modes, ALXP phases, intraday half-day coverage and
  exceptional suspension detection remain unresolved. Calendar admission is bounded
  to 2026–2027; no extrapolation to later years is established.
- No performance history before the broker reference, exact historical TWR, XIRR,
  annualized return or guaranteed historical fee treatment. Modified Dietz remains
  an estimate sensitive to flow dates/size and valuation-source differences.
- No new independent alerting, recovery-drill or latency/CPU-budget acceptance is
  established by release publication. Broader portfolio/provider and analytics work
  is excluded from this release record.
