# PEA Tracker v1.1.3 — Explicit Access reconnection

23 November 2026. Small recovery-interface patch preserving the V1.1.2 financial
confirmation design and the V1.1.1 tracking-safe navigation.

## Changes

- The financial confirmation error page offers an explicit **Reset my Access
  connection** button after `invalid_token`, only on same-origin GET navigation
  with a UUID proposal path.
- The button uses Cloudflare's documented application-domain logout/return flow.
  Its return destination is constructed server-side for the same proposal, without
  tracking parameters or a client-selected redirect.
- A visible warning explains that logout affects other Access applications and
  may require reconnecting the MCP connector. Nothing happens automatically.
- The button helps users attempt session recovery. **It does not diagnose or fix
  the underlying cause of `invalid_token`**, and successful owner reconnection is
  not yet production-validated. Expired proposals still need new preparation.

## Security and validation

- Access policy, identity/audience checks, CSRF, expiry, proposal fingerprints,
  one-use approval, idempotency and financial rules remain unchanged. Clicking the
  reconnection link cannot approve or record a financial operation.
- Seven targeted tests passed, with 27 unrelated cases skipped, plus TypeScript
  and diff checks. Coverage includes the explicit link, warning, fixed return
  destination, absent automatic redirect, GET-only behavior, malformed identifiers,
  denied foreign origins and unchanged proposal/journal state.
- Anonymous inspection confirmed that the existing confirmation redirect selects
  the browser audience, not the MCP audience. This does not establish why the
  owner's authenticated assertion was rejected.
