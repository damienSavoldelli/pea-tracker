a child table references `transaction_journals` before that parent table is created.
No migration was attempted on that failed copy.

the remaining original statements. Retain every statement and every SQL literal;
do not rewrite amounts, JSON, identifiers, references or triggers. The remaining
statement order, including the export's foreign-key deferral, is retained. This
changes only restore DDL order, not the encrypted source dump or project migrations.

Verification before using the reordered input established:

- Identical multiset of original SQL statements.
- Identical reference SQLite rows and final schema with either ordering.
- Successful D1-local import, then full reference/local row and schema equality.
- Foreign-key checks through local D1 and native SQLite; native integrity checking
  on the disposed local database file (D1's API rejects integrity_check itself).

The failed disposable local state was removed before the clean restore. No existing
production table was reset and no source migration or financial guard was edited.
A private recovery helper for the qualified ordering accompanies the encrypted
