## Delivered scope

- A chronological, immutable financial journal for already executed buys/sells,
  deposits, withdrawals, received dividends, declared fees and reversing entries.
  EUR only, explicit portfolio ownership, idempotency and concurrency controls;
  overselling and negative cash are rejected.
- Current positions and cash projected from the selected opening plus journal.
  Remaining cost, weighted-average unit cost (PRU), realized and unrealized gains
  are calculated in the domain with exact fractions. Decimal representations use
  half-even rounding at 18 places; rounded displays never replace exact results.
  Buy fees are capitalized; sell fees reduce proceeds. Dividends credit actual cash
  received without changing quantity or PRU. Historical opening-fee treatment remains
  unknown and is not relabelled as either fee-inclusive or fee-exclusive.
- A separate Bourse Direct operational reference for the close of **20 November
  2026**, retaining the existing real portfolio and immutable historical V1 opening.
  The approved import was checked against all 20 source positions and separately
  evidenced cash. No transactions for the missing intervening period were invented.
- Economic gain in EUR since the selected broker market-value reference, adjusted
  for subsequent deposits/withdrawals. Estimated Modified Dietz percentage return
  weights signed external flows by elapsed UTC time. Dividends and fees already
  included in current value are not counted twice. Missing or incompatible inputs
  produce explicit unavailable statuses; opening PRU never substitutes for market value.

## REST/MCP architecture and security

REST/MCP adapters reuse the application services, domain and Memory/D1 ports.
Historical V1 REST/MCP reads remain compatible; current V1.1 reads are explicitly
separate. The deployed financial composition uses the existing reader Worker and
D1; quotation ingestion and its credentials remain separate.

The 18 MCP tools provide 11 reads/diagnostics, six preparations and one confirmation.
Cloudflare Access/Managed OAuth authenticates the owner. `portfolio:write` is
distinct from technical administration, ingestion and browser-only
`portfolio:approve`. Preparation creates a short-lived immutable intent; independent
owner browser approval uses a distinct Access audience, an exact-content digest and
a one-use server approval. A client Boolean or MCP annotation cannot authorize a write.
These tools journal broker operations; they never place brokerage orders.

## Calendar, freshness and monitoring

The bounded 2026–2027 calendar now separates venue closure dates from individual
continuous/fixing schedules. Production assignments cover **19 XPAR instruments for
fully closed days only**. The last established session is distinguished from an older
missing session. On trading days, intraday phases and half-days remain `unknown`
without an individually qualified profile; BOA Concept (ALXP) remains `unknown`.
No continuous mode is inferred from the MIC. Existing freshness thresholds and
quotation-source/delay warnings are retained.

Cloudflare schedules the existing GitHub Actions collector and monitoring jobs.
The 20:09 Paris closing check was observed successful on 20 November. Partial
collections already fail the collector even if their batch reaches ingestion;
the V1.1 regression checks preserve this distinction. No additional monitoring
service or production-monitor configuration change was needed for final delivery.

## Validation and limits

The final financial Worker version was
`84f0d820-dd10-4f81-9c60-6c83e48e591d`. Local/integration tests, migrations,
deployment checks and owner-reported ChatGPT acceptance are distinguished in the
[validation and RETEX record](v1.1.0-validation.md). They are not a new acceptance
campaign performed by this document.

- The first real owner-approved browser → write → unique receipt/replay journey
  is **not yet validated in production**. Synthetic integration coverage is not a
  substitute; no fictitious real-PEA transaction was created for acceptance.
- Individual continuous/fixing modes remain unqualified. Calendar coverage is
  partial, bounded to 2026–2027, and does not detect exceptional suspensions.
- Performance before 20 November 2026 is not reconstructed. Modified Dietz is a
  non-annualized estimate, not an exact historical TWR; large flows and timing affect
  its accuracy. The broker closing reference is precise to a session date, not an
  invented trade timestamp; initial/current valuation sources may differ.
- Quotations are not guaranteed to be real time. Missing prices or unknown/stale
  freshness retain explicit coverage limitations and warnings.
- Monitoring still depends on GitHub; independent alert delivery and recovery drills
  are not established by these records. No independent external heartbeat is configured.
- Broader portfolio/provider expansion, historical market-data analytics and
  Trading Lab are not delivered by this release.

No private holdings, PRU values, cash amounts, identifiers or credentials are published.
